# DESIGN.md — Arihant Group

Aesthetic lane (named): **trade-house signage meets modern Indian retail.** References: the brand's own collateral (white pages, vermillion chevron bullets, charcoal contact panel), stitched fabric labels, painted wholesale-market signage. Explicitly NOT: editorial-magazine (italic display serif + mono labels), SaaS-minimal, luxury-whisper.

Inverse test: a competitor distributor's site is "blue corporate template, stock warehouse photo carousel, WordPress theme." Nothing here may resemble that.

## Color — OKLCH, "Committed" strategy

The brand already committed: vermillion chevron + charcoal + white (identity preservation wins). Vermillion carries CTAs, index marks, and one drenched band per page; charcoal carries full-bleed sections (like their contact page); paper stays neutral (never cream).

```css
:root {
  color-scheme: light;
  --paper:            oklch(0.985 0.002 30);  /* body bg — near-neutral, NOT cream */
  --paper-shade:      oklch(0.955 0.004 30);  /* alternating quiet band */
  --ink:              oklch(0.215 0.010 30);  /* headings, body on paper */
  --ink-soft:         oklch(0.44 0.012 30);   /* secondary text on paper (≥7:1) */
  --charcoal:         oklch(0.245 0.010 30);  /* full-bleed dark bands (their collateral) */
  --charcoal-raise:   oklch(0.30 0.012 30);   /* raised surface on charcoal */
  --on-charcoal:      oklch(0.975 0.003 30);
  --on-charcoal-soft: oklch(0.81 0.008 30);   /* ≥4.5:1 on charcoal */
  --vermillion:       oklch(0.58 0.19 29);    /* brand red #D04030 — large type, marks, drench */
  --vermillion-deep:  oklch(0.485 0.185 29);  /* buttons + red text on paper (≥4.5:1 white-on-it) */
  --vermillion-drench:var(--vermillion-deep); /* red canon: equals --vermillion-deep — one drench/interactive red */
  --line:             oklch(0.885 0.006 35);  /* hairlines on paper */
  --line-dark:        oklch(0.38 0.012 30);   /* hairlines on charcoal */
  --focus:            var(--vermillion-deep);
  /* unit accents (decorative identity only — CTAs stay vermillion sitewide) */
  --unit-marketing:   oklch(0.40 0.15 28);    /* maroon from their logo (#900000) */
  --unit-apparels:    oklch(0.28 0.012 30);   /* ink — crown-black identity */
  --unit-retail:      oklch(0.46 0.17 310);   /* purple from their logo (#7030A0) */
}
```

**Amended (change brief, G7):** one colour joins the palette, `--whatsapp` / `--whatsapp-deep`. It is a platform identity colour, not a second brand red, and it is allowed on WhatsApp affordances ONLY: the desktop FAB, the WhatsApp cell of the mobile action bar, the header contact pair, and the mark beside the hero's brand-list link. It never appears on a page CTA. The deep tone is WhatsApp's own `#128C7E` rather than `#25D366`, chosen so a white glyph clears 4:1 on it (measured 4.13:1).

Rules: buttons/CTAs are always `--vermillion-deep` (one primary action color sitewide). Red canon: `--vermillion-drench` is set equal to `--vermillion-deep` — a single interactive/drench red sitewide (the token name survives for compatibility); `--vermillion` is reserved for large display type and low-alpha motifs. `--unit-*` may color the unit plate, index marks, underlines, and motif tints on that unit's page only. Never gray text on colored grounds — use deeper same-hue or alpha of the text color. No gradients anywhere (flat trade palette); no gradient text; no glassmorphism. On /arihant-retail the store atlas may use `--unit-retail` for its map marks only: route stitches, store pins, and the ownership marks in its key and list. None of these is the hover cue. (Change round 4: the land tint is retired with the square-pixel map. The terrain is a committed shaded-relief image, which is imagery and not a CSS gradient; the atlas alone may use its own `--atlas-water` slate blue for rivers.) Swing tags are ink (charcoal = company-owned, ink-framed paper = franchisee-owned); the active state is ink (tag lift, an ink frame round the pin, a 3px ink rule over the entry). No vermillion inside the map.

## Typography — Google Fonts, via `next/font`

- **Besley** (variable; weights 500–900 + italic) — display and headings. Clarendon-slab trade-poster DNA: sturdy, warm, established. Set dark and tight. Heading emphasis is carried by colour, upright, never italic (change round 3, sitewide: `EmphasisHeading` sets `fontStyle: normal` explicitly, because a browser renders `em` in italics by default). Italic survives only in quotations (testimonials, pull quotes), never as heading emphasis.
- **Archivo** (variable; width + weight axes) — body, UI, labels, numbers. Signage heritage. Condensed-width caps for big stat figures (`font-stretch` ~85%); `font-variant-numeric: tabular-nums` on all stats.

Both chosen by the register's font procedure (voice words: steadfast / industrious / warm-handshake; reflex picks Fraunces·Inter·Playfair rejected per skill ban list).

Scale (fluid, ratio ≥1.25):

```css
--text-display: clamp(2.6rem, 1.1rem + 5.2vw, 4.75rem); /* Besley 800, lh 1.06, ls -0.015em */
--text-h2:      clamp(2.0rem, 1.1rem + 3.4vw, 3.4rem);   /* Besley 700, lh 1.12 */
--text-h3:      clamp(1.45rem, 1.1rem + 1.4vw, 2.05rem); /* Besley 700, lh 1.2 */
--text-h4:      1.3rem;                                   /* Archivo 650, lh 1.3 */
--text-lead:    clamp(1.13rem, 1rem + 0.5vw, 1.3rem);     /* Archivo 400, lh 1.55 */
--text-body:    1.0625rem;                                /* Archivo 400, lh 1.65 */
--text-small:   0.9375rem;
--text-label:   0.8125rem;                                /* Archivo 650, caps, ls 0.07em */
--text-stat:    clamp(2.6rem, 2rem + 3vw, 4.4rem);        /* Archivo 800 condensed, tabular */
```

`text-wrap: balance` on h1–h3; `text-wrap: pretty` on prose; body measure ≤ 68ch. On charcoal, add +0.07 to line-heights. Display letter-spacing never tighter than −0.04em.

## Hero grammar (kickers retired)

There are no kickers, eyebrows, or thread labels anywhere — the thread-label system was retired. Heroes carry their weight through oversized Besley display type, imagery, and the accent rule alone; headings are written to stand without a tag above them. Hero headlines run short — ≤6 words — with the lead beneath carrying the numbers (the shorter `--text-display` ceiling assumes this). Where the client has set a sentence as a headline (the Apparels tagline, about 100 characters), `EmphasisHeading` adds `.t-display--long` past 80 characters: one step down (0.74×), wording untouched. Inner sections get plain scaled headings — no eyebrows, no numbered markers (numbers allowed only inside true sequences like the 4-step partner process).

## Imagery

Real assets first (from the brand profile): 3 store photos (`public/images/photos/`), 77 partner logos (`public/images/partners/`), 3 unit logos, the chevron motif. **The 3 real store photos always outrank stock in placement.** The storefront photo whose sign reads URBAN CLOSET is attached to no store (change round 3): it was captioned as the Itanagar store, which its sign contradicts, so it runs uncaptioned as `photoSlots.retailStorefront` on /partner until the client confirms which store it shows. `store-ebo-indian-terrain.jpg` stays unplaced (a single-brand outlet with third-party fascias; contradicts the multi-brand pillar). From 768px up, real photos under 500px wide render no wider than 15.5rem with no parallax overscan; on a phone the retail hero shows its two photographs side by side under the copy (since change round 5; their ~400px originals are what keeps them from running larger, until bigger files are supplied).

Photography is addressed through `src/content/images.ts`, which carries two registers: `photoSlots` (one named key per photographic position, with its ratio reserved, honest alt text and `real: true|false`) and `stockImages` (the library those slots draw from). A slot marked `real: false` carries a `wanted` line saying what to shoot; swapping the real photograph in is a one-line edit and nothing around it moves. `pendingPhotoSlots()` lists what the shoot still owes. Stock stays until replacements land, then goes.

Stock policy: curated local royalty-free photography (Unsplash/Pexels licenses; commercial use, no attribution required) is downloaded once and committed under `public/images/stock/{hero,trade,retail,blog}/`, ≤450KB each, ~2000–2400px long edge. Pages reference stock ONLY via the typed manifest `src/content/images.ts` (`{src, alt, width, height, credit, sourceUrl}`) — never by ad-hoc path. Authenticity filter: Indian garment-trade context (fabric bolts, garment racks, warehouse shelving, cartons, Indian storefronts/markets, tailoring hands); reject Western-office clichés, visible third-party logos, and AI-looking imagery. Stock is generic trade context and never masquerades as Arihant's own facilities.

Logo tiles: white tile, 1px `--line` border, logo `object-contain` with ~20% padding, uniform 3:2, full color (the /brands wall, unit-page walls, partner modal). The home marquee is the one tile-less exception: transparent cutouts on the section ground (see Motion, Marquee). Photos: full color, slight contrast, 6px radius, 1px border; alt text in brand voice, honest about what is known ("Inside an Arihant Retail floor: merchandised, staffed and stocked by our own team"; never a town or store name the photograph cannot confirm). Blog cards and post headers use 3:2 thumbnails (`next/image`, explicit dimensions, accurate `sizes`).

## Motion — GSAP

- Stack: `gsap` + `@gsap/react` (`useGSAP`). ScrollTrigger and SplitText are registered exactly once in `src/lib/gsap.ts` (`"use client"`); every animated component imports GSAP only from there. Motion primitives live in `src/components/motion/`. All GSAP plugins are free (Webflow acquisition) — SplitText needs no auth token.

## Mobile layer (≤767px)

The phone experience is designed, not derived. It keeps the same copy word for word, the same palette and the same two typefaces, and every piece of content stays reachable; what changes is composition, rhythm and interaction. **Amended (mobile revamp, October 2026):** phones may also reorder elements within a section and condense (rails, accordions, merged rows). The original rule also kept every section in the same order; sections still run in page order, and nothing moves out of reading order (a visual reorder that a keyboard or screen reader would meet in a different order is not allowed).

**Containment rule.** Everything lives in `src/app/mobile.css`, and every rule is inside `@media (max-width: 767px)`. Desktop rendering at ≥768px is therefore frozen by construction: nothing in that file can reach a 768px viewport. Since the mobile revamp the phone bottom-sheet variant of the modal lives there too (section 25; it used to sit in globals.css). JSX may add only inert, component-prefixed hook classes (`footer-unit__head`, `leader__plate`) and phone-only markup marked `md:hidden`, never a new Tailwind utility: Tailwind v4 generates a rule for any utility-shaped word it finds in the source, comments and this document included, and that rule would reach desktop.

**The import must stay at the FOOT of `globals.css`.** It was at the top, and an `@import` is inlined where it is written, so every mobile rule landed BEFORE this file's own rules. A media query adds no specificity, so `:root`, `.section-pad`, `.t-display` and every other selector present in both files resolved to the DESKTOP value at 360px — the phone type scale, the phone section rhythm and the phone action bar had never applied on the live site. Only rules with no twin in globals.css (the `--m-*` variables, `.m-rail`, `.m-bleed`) were surviving, which is why the layer looked half-alive rather than absent.

**Proof.** Superseded by the mobile revamp, which reinstated the byte-diff and added pixel checks (scripts and evidence in `MOBILE-REVAMP-STATUS.md`): (1) `scratchpad/check_mobile_containment.py` (v2) asserts that every query in mobile.css is bounded below 768px (v1 only looked for the text "max-width") and that no other stylesheet carries a phone-only query; (2) the compiled desktop CSS of every route, phone blocks stripped, must hash identically before and after; (3) headless screenshots from 768 to 1920px wide, with a computed layout signature, must match the baseline (clear `.next/cache/images` before comparing pixels: a re-encoded photo differs by a few pixels on its own). The file is unlayered, so a plain selector beats any Tailwind utility (`gap-12`, `grid-cols-3`, `aspect-[4/5]`) with no `!important`. Inline `style` still wins over CSS, so component-level sizes are written `var(--m-x, <desktop value>)` and retargeted by defining `--m-x` in the mobile token block — on desktop the variable is undefined and the fallback is the original value.

**Type.** The desktop scale bottoms out on its clamp floor at phone widths, collapsing the display-to-h2 step. Mobile redefines the tokens to grow with the handset from 360 to 430px: display `clamp(2.25rem, 0.3rem + 8.4vw, 2.625rem)` (35 / 37.6 / 41px), h2 `clamp(1.75rem, 0.55rem + 5.2vw, 2rem)`, h3 `clamp(1.375rem, 0.73rem + 2.86vw, 1.5rem)` (mobile revamp; the old display `clamp(2.35rem, 9.6vw, 3.05rem)` sat on its floor at every phone width). Nothing on a phone sets below 13px (`--text-label` 0.8125rem; two exceptions at 11px: the tracked GROUP of the wordmark, and the "Store photo coming soon" tag inside the retail map card's 9rem drawing). Long headlines (`t-display--long`, `t-display--feature-long`, the retail fit hero) step down to `clamp(1.95rem, 0.3rem + 7.6vw, 2.3rem)`, and the home headline is sized from its column so it always sets in three lines. Marketing pages read at 16px/1.6; the article body alone runs 17px/1.72.

**Rhythm.** `.section-pad` is `--m-section` (3.25rem) on a phone. `.m-flow` / `.m-flow-tight` / `.m-flow-loose` (1.75 / 1 / 2.5rem) replace desktop `gap-8/10/12/14` on section wrappers. The gutter is `--m-gutter`, `clamp(1.25rem, 0.35rem + 4vw, 1.5rem)`, and the phone `:root` also sets `--gutter` to it, so containers, bleeds and rails agree (two sticky drawings used to bleed by an undefined `--gutter`).

**Surfaces (mobile revamp).** One language on a phone: *plates* for things tapped whole (white, a 1px line, a 10px radius, no shadow at rest: the funnel cards, testimonial cards, intent cards, the contact address); *ledgers* for facts and links (hairline rows at least 44px tall: awards, footer units, FAQs, the about leaders, contact channels, the Trade Notes rows, the partner steps on their spine); *bleeds* for photographs and dark bands (edge to edge, no radius). Buttons stay sharp at 2px and grow to 48px (52px large), with a pressed state; only floating things cast a shadow (the dock, the deck, the swing tags). Every section heading carries a short vermillion rule above it (`.section-head`, from `SectionHeading`; white on the drench, the large-mark red on charcoal): a rule, not a label, so the no-kicker rule stands.

**Idioms.** `.m-bleed` runs photography and dark bands edge to edge (the strongest "made for this screen" cue). `.m-link` is the phone text link: always underlined (there is no hover to reveal it), a 44px row, its arrow kept out of the underline. `.m-plate` is the plate surface. `.m-rail` turns a grid into a CSS scroll-snap carousel with a peeking next card — used for the home Trade Notes teaser, the proof strip, testimonials and the recognition cabinet (the business tickets are gone; since the mobile revamp the two home funnel cards stack so both asks are on screen together, and the Trade Notes index is a lead card then compact rows) (the retail store list is a vertical ruled list under the map instead, so a tapped chip and its entry share a screen); it works with JS off, and every rail either holds links or carries `tabindex` itself. `.m-cta` stacks calls to action full width. `.press` supplies the tap feedback that hover states cannot.

**Motion.** Mobile is no longer one fade repeated: `HeroIntro` runs the masked line rise at a quicker cadence; `Reveal`'s three variants stay three distinct moves; `StaggerGroup` keeps its direction at half travel and gains `mLedger` (a left-to-right wipe that rules hairline rows in); `ParallaxImage` drifts at half amplitude on `mBleed` frames only; `CardsStack` pins the deck alone, clear of the header and above the dock, and falls back to the plain column where the gathered deck does not fit (since the mobile revamp its phone stage is the deck plus room for the cards to rise through, at least 52svh, pinned by its top under the header: the clearance is the `scroll-margin-top` of the column, which CardsStack reads; it used to be a full screen pinned by its bottom with the deck centred, which opened a screen-high gap under the heading); `Timeline` draws its spine to the thumb; `NetworkMap` draws its arcs once instead of looping. Rails animate with scale and opacity only, never translation, which would grow the scroll area and make the rail twitch.

**Shell.** On a 360px handset the bar has to hold the wordmark, the Call/WhatsApp pair and the menu button; the wordmark steps down (`--m-wordmark`) and the bar's gaps tighten, because at desktop size the menu button was being squeezed to zero width and a phone visitor had no way to open the menu (found and fixed in change round 2; it was live on the deployed site). The menu sheet carries a direct Call/WhatsApp row above the safe-area inset; `StickyActionBar` yields whenever a `.drench-band` or `#inquiry` is on screen, so the page's own ask is never doubled. **Mobile revamp:** the bar is 3.5rem under its rule and the wordmark stacks (ARIHANT over a tracked GROUP), with a hairline before the menu button. The header publishes `--m-header-offset` (how much of it is on screen) from a phone-only matchMedia context, and sticky elements sit at `--m-sticky-top`, so they follow it as it slides away and back instead of leaving a header-sized gap. The menu sheet sets the businesses as ruled 56px rows with their logos and the pages large in Besley. The action bar is a floating charcoal dock (Call, WhatsApp, the vermillion Inquire) inset from the screen edges above the safe area; it looks the CTA bands up again on every route (`useRivalCtaOnScreen(routeKey)`: it used to look once, so after a client-side navigation it stayed up over the next drench) and also stands down over the footer, which carries every contact line. The footer runs the reach line over the dotted NetworkMap (texture at this size, its hub label hidden), folds the three units into a native exclusive accordion (`ContactAccordion`, `details` elements sharing a `name`, `md:hidden`; the desktop columns are hidden on a phone) and runs the office map edge to edge at 9.5rem: about 900px against 1692.

## Accessibility & performance bar

Body contrast ≥ 4.5:1 (verify every pairing; muted text included), focus-visible 2px `--focus` ring + 2px offset on ALL interactive elements, skip link, sequential headings, form labels + `aria-live` errors + focus-to-first-error, touch targets ≥ 44px, `tap-highlight` handled. Static generation for every route; `next/image` for all raster; fonts via `next/font` (swap, subset latin); **exactly one** third-party script is permitted, Plausible, and only when `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` is set (change brief, G10). It is cookieless and stores no personal data, which is why this site needs no consent banner. One third-party frame exists since change round 7, at the client's request: the footer's Google Map (`mapsEmbedUrl()`, `loading="lazy"`). It is not a script on the page, but Google may set its own cookies when it loads; if a consent banner ever becomes a requirement, make it click-to-load rather than add a banner. Nothing else: no other trackers, no CDN embeds, no map iframes. A map must be a committed image file or inline SVG drawn from committed static data (NetworkMap, the store atlas), never an embed; directions are plain external Google Maps links. Bundled npm deps like `gsap` and `lenis` are fine; marquee/count-ups cause no CLS (reserve space).
