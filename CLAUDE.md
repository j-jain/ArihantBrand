# Arihant Group Website

Premium, conversion-focused marketing site for the Arihant group (Guwahati): Arihant Marketing, Arihant Apparels, Arihant Retail. Next.js 16 App Router + TypeScript + Tailwind v4 + Sanity (embedded Studio at `/studio`).

**Read before designing or writing UI:** [PRODUCT.md](PRODUCT.md) (who/what/voice/honesty rails) and [DESIGN.md](DESIGN.md) (tokens, type, layout grammar, motion, component specs). They are binding.

> **Next.js 16 warning:** this Next version has breaking changes vs training data (async request APIs, params as Promises, config changes). When unsure about an API, read the bundled docs in `node_modules/next/dist/docs/01-app/` before writing code.

## Hard rules

- All copy/data comes from `src/content/` (seed) or Sanity — never hardcode contact info, stats, or partner names in components.
- No invented facts, numbers, or testimonials. Franchise economics stay qualitative.
- No em/en dashes in user-visible copy — restructure the sentence instead.
- Fonts: Besley (headings) + Archivo (body/UI) via `next/font/google` only.
- Colors: OKLCH tokens from DESIGN.md; CTAs are always `--vermillion-deep`; a single interactive red sitewide (`--vermillion-drench` equals `--vermillion-deep`); unit accents are decorative only.
- No kickers/eyebrows anywhere — the thread-label system is retired; heroes carry their weight through type and imagery. No numbered markers on inner sections (numbered steps allowed only for true sequences).
- Imagery: the 3 real store photos always outrank stock. Stock is curated local royalty-free files committed under `public/images/stock/`, referenced only via the typed manifest `src/content/images.ts`.
- Motion is GSAP-based (`gsap` + `@gsap/react`; plugins registered once in `src/lib/gsap.ts`), gated via `gsap.matchMedia()` for reduced-motion and mobile; initial hidden states set only from JS (one exception: the hero intro gate, `html[data-intro]` set by an inline head script in `app/layout.tsx`, hidden in `motion.css` with a 3s failsafe and lifted by `HeroIntro`; see DESIGN.md). Lenis (`lenis`) drives smooth scroll on desktop fine-pointers only (synced to the GSAP ticker). The Wave-B motion primitives (FlipWords/FlipLead, VapourText, SplitHeading, CurtainReveal, CardsStack [the pinned "Why us?" deck: one ScrollTrigger pin, JS-only `data-deck`, static column as the fallback], TestimonialColumns, NetworkMap [footer dotted map of the Northeast, reach arcs pause offscreen], the pixel word [`HeroIntro pixelEmphasis` + `motion/pixelWord.ts`, home hero only], rebuilt Timeline) live in `src/components/motion/` + `src/app/motion.css`. The store atlas is page-local, not a primitive: `src/app/(site)/arihant-retail/_components/` + `src/app/atlas.css` (retail only; since change round 4 a realistic terrain map: a committed relief image plus SVG borders, rivers and labels generated by `scripts/build-atlas-map.mjs` into `atlasMap.data.ts`, all through `atlasProjection.ts`; re-run the script, never hand-edit its outputs; hover cards show the store's photo, a credited town photo from `townPhotos`, or else a drawn shopfront with the store's name (`StorePlaceholder`, change round 5: never a stock photo); one build then still; it must never resemble NetworkMap). Since change round 5 the retail hero (`UnitHero fit` + `RetailHeroPhotos`, photos revealed through HeroIntro's `[data-hero-clip]`) and the model band (`ModelBoard fit`) each fit one screen from 768px up. `EmphasisHeading` sets hyphenated words nowrap (`.nobr`) so a SplitHeading heading wraps the same before, during and after its split. ParallaxImage's `tilt` prop adds pointer-tracked tilt on photographic images only (fine pointers ≥1024px); its `fillHeight` prop drops the intrinsic ratio so the frame can take its height from a stretched grid column. Any tween that animates `clipPath` must `clearProps` it on completion — a resting `inset(0)` still clips to the border box and slices focus rings off edge-flush controls.
- **One composition from 768px up.** Tablet to wide monitor is a single arrangement that scales through the root font size (see DESIGN.md, layout grammar). Never add `lg:`/`xl:` layout switches or `min-width: 1024px` layout queries; a composition change happens at 768px or not at all. Size in rem, not px, so it scales. Behaviour gates (tilt, Lenis) may stay at 1024px. The header's menu button below 1024px is the one documented exception.
- **Sanity is the live source, and seeding is a publish.** With `.env.local` set, the site reads Sanity first, and the dataset is the one production reads. Edit copy in `src/content/`, preview it locally with `SANITY_READS=off` (set in `.env.development.local`), and before `npm run seed` diff the seed against the live dataset (`node scripts/seed.mjs --dry-run --out=<file>`) so Studio edits are ported into the seed rather than overwritten. Seed only after the matching code is deployed. `seed.mjs` never deletes: retired documents must be removed in the Studio.
- **Mobile is a dedicated layer, and desktop is frozen.** All phone-specific styling lives in `src/app/mobile.css`, and every rule in that file sits inside `@media (max-width: 767px)`. Never restyle mobile by editing a base Tailwind utility or a shared component rule — add a hook class and style it there. The file is unlayered, so it beats Tailwind utilities without `!important`. Where a component sets size inline, write it as `var(--m-x, <desktop value>)` and define `--m-x` only inside the mobile block. Motion follows the same rule: mobile changes go in the `mobile:`/`max-width: 767px` branch of an existing `gsap.matchMedia()`, never in a desktop branch. Verify with the CSS diff described in DESIGN.md — stripping the mobile blocks must leave desktop CSS byte-identical.
- Contrast ≥ 4.5:1 body text everywhere; visible focus rings; `prefers-reduced-motion` alternatives for all animation; content never hidden behind un-triggered animations.
- Every route must build statically and render fully without Sanity env vars (seed fallback via `src/lib/content.ts`).

## Commands

- `npm run dev` / `npm run build` / `npm run lint`
- `npm run seed` — import seed content into a configured Sanity project (see SETUP.md)

## Structure

- `src/app/(site)/` — public routes (incl. `/recognition`) · `src/app/studio/` — Sanity Studio
- `src/app/globals.css` imports `src/app/motion.css` (Wave-B component styles) + `src/app/form.css` + `src/app/atlas.css` (the retail store atlas, page-local components in `src/app/(site)/arihant-retail/_components/`) at the top, and `src/app/mobile.css` at the foot
- `src/components/` — shared components (see DESIGN.md component list)
- `src/content/` — types + seed content (fallback data source)
- `src/lib/` — content data layer, sanity client, seo helpers
- `src/sanity/` — schemas + studio config
- `public/images/atlas/` — the store atlas's relief image (generated, see above)
- `public/images/` — logos/ (the three business logos: transparent cutouts written by `scripts/cutout-unit-logos.mjs` from `assets/unit-logos-original/`, sharing the partner script's keying; re-run, never hand-edit; the seed uploads them to Sanity), partners/ (77 brand logos: transparent cutouts written by `scripts/cutout-partner-logos.mjs` from the unserved originals in `assets/partner-logos-original/`; re-run the script, never hand-edit the outputs), photos/, motifs/
